# 공식 시간표 → GY 시트 자동 동기화 (timetable-sync) 설계

작성 2026-09-01 · 상태: 설계 승인됨, Phase 0 미실행

## 1. 목적

학과 공식 배포본(총대 관리)이 바뀌면 GY의 구글 시트에 **자동으로 반영**하고, 그 결과가 PWA·위젯·공지까지 흘러가게 한다.

현재 이 구간은 전적으로 수동이다. `guide.html:228`이 그 사실을 사용자에게 안내하고 있다: *"그룹 공지와 공식 시간표를 보는 게 더 빠르게 변경사항을 확인하는 방법입니다.. GY가 가독성 좋게 변경 및 적용하는 데 시간이 걸리므로 양해바랍니다"*. 이 문장이 필요 없게 만드는 것이 목표다.

**이미 자동화된 구간(변경 없음)**: GY 시트 → `snapshot.yml` → `data/snapshot.js` → PWA/위젯.

## 3. 계정·권한 구조 (핵심 결정)

**GAS를 csmedst20224181 계정으로 돌린다.** 공식 파일이 그 계정에 공유돼 있으므로 추가 공유 요청이 필요 없다. 알림만 sbfpo4 Gmail + 카톡으로 넘어간다 — draft-radar가 쓰는 것과 같은 구조.

- 파일 소유자에게 **아무것도 요청하지 않는다.** 단 Phase 0에서 복사 허용이 꺼져 있다고 판명되면, 그때 요청할 내용은 "sbfpo4에 공유"가 아니라 **"뷰어 복사·다운로드 허용"** 이다.
- GitHub Action 경로는 불가: 어떤 구글 계정으로도 로그인돼 있지 않고, 서비스 계정은 공식 파일 접근 권한이 원천적으로 없다.
- 로컬(그램) 실행 경로도 기각: csmedst OAuth refresh token을 로컬에 저장·갱신해야 하는데, GAS에서는 `ScriptApp.getOAuthToken()`으로 그 문제가 아예 없다.
- **GY 액션**: 자기 시트(`1xcH1...`)를 csmedst20224181에 **편집자**로 공유. 본인 계정 둘 사이라 제3자 개입 없음.

## 4. 아키텍처

csmedst 소유 standalone GAS 프로젝트 `timetable-sync`, 15분 시간 트리거.

```
tick()
 1. Drive files.get(공식ID, fields=md5Checksum,modifiedTime)      싼 호출
 2. 스크립트 속성의 직전 해시와 비교 -> 같으면 종료               하루 96회 중 ~95회
 3. 달라졌을 때만:
    a. Drive.Files.copy(mimeType: google-apps.spreadsheet)        임시 네이티브 사본
    b. parse()    공식 시간표탭+학습부배정탭 -> IR
    c. compose()  IR + 레퍼런스 매핑 -> 셀별 블록 + 서식
    d. diff()     GY 시트 현재값과 비교
    e. 가드레일 통과? -> 백업 -> 쓰기 : 보류+알림
    f. v-bump / 공지 기입 / 카톡+메일 / 변경로그 append
    g. finally: 임시 사본 삭제, 해시 저장
```

`md5Checksum`이 안 나오면 `modifiedTime`으로 격하한다.

### 모듈 경계

| 파일 | 역할 | GAS API |
|---|---|---|
| `parse.gs` | 공식 구조 → IR | 없음 (**Node 테스트 가능**) |
| `compose.gs` | IR + 매핑 → 셀 블록·서식 | 없음 (**Node 테스트 가능**) |
| `diff.gs` | 현재 시트 vs 목표 → 변경 목록 | 없음 (**Node 테스트 가능**) |
| `io.gs` | Drive/Sheets 읽기·쓰기·백업 | 있음 |
| `notify.gs` | 카톡·Gmail·공지 탭 | 있음 |
| `diagnose.gs` | 상설 진단 | 있음 |

**IR이 유일한 경계다.** `parse`는 공식 구조만, `compose`는 GY 구조만 안다. 공식 레이아웃이 바뀌면 파서만, GY 서식이 바뀌면 compose만 고친다.

### IR

```js
{ date: '2026-09-03', period: 3, weekday: 4,
  className: '외과 종양학', professor: '류성엽',
  drafter: '강현승', reviewer: '임유진',
  mergeGroup: 'g12' }   // 학습부배정 병합 범위 id (통합 판정용)
```

### 조인 키는 날짜+교시 (행 번호 아님)

공식은 행 3에서 10행 주기, GY 시트는 행 1에서 11행 주기다. 행 산수로 맞추면 어느 한쪽에 행이 하나 끼는 순간 전부 밀린다 — 2026-08-12에 겪은 사고("주 블록을 빠뜨리면 이후 전부 7일씩 조용히 밀렸음")와 같은 부류.

날짜 조인의 부수효과: **공식에 대응 좌표가 없는 곳은 애초에 쓰기 대상이 되지 않는다.** 26-1 구간, 토·일 열, 저녁 행이 규칙 없이 자동으로 보호된다.

## 5. 셀 재조립

셀 = **생성 블록 + 보존 블록**. 순서는 항상 수업명 → 교수 → 학습부 → 메모.

| 블록 | 줄 수 | 출처 | 판정 |
|---|---|---|---|
| 수업명 | 1~2 | 공식 시간표 탭, 마지막 괄호쌍 앞부분 | 나머지 앞부분 |
| 교수 | 0~1 | 교수=공식 / 약어=레퍼런스 매핑 | 괄호로 감싼 줄 |
| 학습부 | 0~2 | 이름=공식 학습부배정 탭 / 라벨·번호=규칙 | `라벨N: 이름/이름` |
| 메모 | 0~n | **GY** | `#`로 시작 |

**빈 줄은 넣지 않는다.** 교수가 없는 셀(`PBL3`·`법의학`·`과정형성평가` 등 **281칸**)은 지금처럼 1줄로 남고 앱 화면은 바뀌지 않는다. 블록 경계는 위치가 아니라 형태로 판정하므로 위치 고정이 필요 없다.

- 수업명·교수 분리는 **마지막 괄호쌍** 기준. `소아혈액학: 빈혈, 출혈질환(고영권)`처럼 콜론·쉼표가 섞여도 안전.
- **미등록 교수는 추측하지 않는다.** 약어 없이 쓰고 알린다.
- 수업명의 수동 개행(`신경계질환 검사 / 및 보조진단`, r373C)은 **공식 표기를 따른다** — 특정 지점 접기는 자동화가 지킬 수 없다.

### 시간순 번호

과목(라벨)별로 모든 수업을 `(날짜, 교시)` 오름차순 정렬 → 1부터. 2026-08-31에 GY가 정한 규칙.

**통합** — 학습부배정 탭에서 **연속 교시가 하나로 병합된 범위**. 한 팀이 두 수업을 맡는다. 26-2에 **12건**.

```
변경 전  r246C: 종양의 병기 / (류성엽, Upper GI Surg) / 혈종2-1: 강현승/임유진
        r247C: 외과 종양학 / (류성엽, Upper GI Surg) / 혈종2-2: 강현승/임유진

변경 후  C246:C247 병합
          종양의 병기
          외과 종양학              <- 수업명 블록 2줄
          (류성엽, Upper GI Surg)
          혈종2: 강현승/임유진      <- 번호 하나, -N 없음
```

교수가 다른 통합은 26-2에 **0건**이지만, 다를 경우 교수 블록을 2줄로 쓰는 분기를 넣는다.

판정 근거는 **병합 범위**여야 한다. "담당자 이름이 같음"으로 판정하면 우연히 같은 팀이 연속 배정된 경우에 오탐이 난다.

**분할** — 한 수업에 두 팀. 셀이 하나뿐이라 병합 대상이 아니고 `-1`/`-2`를 **유지**한다. 26-2에 2건:

```
r354F  당뇨병의 급성합병증과 저혈당 / (김상용, Endo)
       내분비11-1: 이세훈/안성민
       내분비11-2: 김예찬/박지영

r366D  뇌혈관질환 1 / (안성환, Neuro)
       신경4-1: 강준하/임유진
       신경4-2: 이준수/서정우
```

통합에서 `-N`이 사라지므로, 결과적으로 **`-N`은 "한 수업 두 팀"만 뜻하게 되어 표기 중의성이 없어진다.**

**번호가 밀리면** 카톡 알림에 `혈종2 → 혈종3` 형태로 반드시 찍는다. GY가 외부(초안 파일명·단톡)에 알린 번호와 어긋나는 것은 코드가 해결할 수 없다.

> 메모리 정정: 파란색은 `#2E75B6`이 아니라 **`#2E75B5`**.

### 정체불명 줄은 지우지 않는다

생성 블록 어디에도 해당하지 않고 `#`도 없는 줄을 만나면 **보존하고 알린다** — "3주 화 5교시에 정체불명 줄이 있어 보존했습니다. 메모면 `#`를 붙여주세요."

최악의 결과가 "메모 소실"이 아니라 "알림 한 번 더"가 되도록 하는 비대칭이다.

> `#`은 현재 시트 2,046칸 / 3,161줄에서 **0회** 등장 — 충돌 없음(2026-09-01 실측).

## 8. 가드레일

한 실행에서 초과 시 **쓰지 않고 보류 + 알림**:

- 값 변경 **40칸**
- 병합 변경 **8건** (값과 별도 카운트)
- 삭제(내용 있던 칸 → 빈칸) **10칸**
- 파싱 주차 수가 직전 실행과 다름
- 레퍼런스 미등록 교수·과목 **5건**

임계치는 첫 몇 주 실측 후 조정한다. 정상 변경은 한 자릿수이므로 여유가 크다. 수십 칸이 한 번에 바뀐다는 것은 총대가 갈아엎었거나 파서가 깨졌다는 뜻이고 **둘 다 사람이 봐야 한다**.

## 9. 롤백

- 쓰기 **직전** GY 시트 전체를 Drive 사본으로 (`시간표백업_2026-09-03T1415`). 최근 10개 유지.
- `변경로그` 탭에 `실행시각 / 좌표 / 이전값 / 새값` append.
- **첫 2주는 dry-run**: 계산·diff·알림만, 쓰기 없음, v-bump 없음.

## 10. 앱 반영

**버전 배지** — 쓰기 성공 시 파일명 `v97_시간표_GY` → `v98_시간표_GY`. `^v(\d+)_`로 파싱해 +1, 패턴 불일치면 건드리지 않고 알린다. 배선은 이미 존재한다(`extract.ps1 -Title` → `properties.title` → 앱·위젯 배지). dry-run 중에는 올리지 않는다.

**공지 자동 기입** — `공지` 탭에 `2026-09-03 | 시간표 변경 3건 | 9/4(금) 3교시 수혈의학 휴강 · …`.

> **지뢰**: 날짜는 반드시 **ISO 문자열 `2026-09-03`**, A열 텍스트 서식 유지. 표시 서식 `2026. 9. 3`이 들어가면 마침표가 하이픈보다 커서 모든 ISO를 이기고 `tt_notice_seen`에 박힌다. 그러면 **이후 새 공지에 빨간 점이 영영 안 뜬다.**

같은 날짜 행이 있으면 새 행 대신 내용에 이어붙이고 제목 건수만 갱신한다. 공지는 **동기 전원에게 보이므로** GY 개인 배정은 넣지 않는다.

## 11. 알림·운영

카톡(나에게 보내기) + sbfpo4 Gmail. **카카오 앱은 새로 만든다** — 앱을 공유하면 양쪽이 각자 refresh_token을 갱신하다 서로를 무효화한다(draft-radar SETUP.md).

보내는 것: ① 반영 완료(변경 요약 + 밀린 번호 + v-bump) ② 가드레일 보류 ③ 미등록 교수·과목·색 ④ 정체불명 줄 ⑤ 실행 예외 ⑥ **24시간 무성공 시 알림**(조용한 죽음 방지).

- 코드 정본 `C:\claude\timetable-sync\` + git, clasp로 push/pull. 월 백업 편입.
- **시크릿은 스크립트 속성에만.** git·백업·채팅 금지.
- 설정 분리: ID·시크릿 → 스크립트 속성 / 매핑·임계치·시험 키워드 → 레퍼런스 탭(GY가 폰에서도 조정).
- `SETUP.md`는 draft-radar 형식.
- clasp 설치 시 주의: 메모리에 *"npm은 ExecutionPolicy에 막혀 안 돎"* 기록이 있어 `npm.cmd` 또는 Bash 경유가 필요할 수 있다. **미검증.**

## 12. Phase 0 — 코드 작성 전 확정할 미결 5건

`diagnose()` 1회 실행으로 전부 확인한다. 상설로 남긴다(2026-08-15 교훈: *"그때 원인을 가릴 단서가 0이었던 게 진짜 문제"*).

| # | 확인 | 틀렸을 때 |
|---|---|---|
| 1 | 공식 셀 줄바꿈이 실제 개행인가 워드랩인가 | 수업명/교수 분리 로직 |
| 2 | 학습부배정 통합이 병합 범위로 표현되는가 | 통합 판정 근거 재설계 |

## 13. 성공 기준

1. 공식 파일 변경 후 15분 내 GY 시트 반영, 카톡 알림 도착.
2. 반영 결과가 GY가 손으로 하던 것과 **셀 단위로 동일**(첫 실행 diff로 검증).
3. 무접촉 영역(26-1·토일·점심·저녁·`#` 메모)에 변경 0건.
4. 앱 배지 v-bump, 공지 빨간 점 확인.
5. 2주 dry-run 동안 가드레일 오발동 0건.
