- 날짜: 2026-08-12
- 대상: 시간표 PWA (`C:\Users\wbnuj\timetable-pwa`, 배포 `pureart-art/Timetable26-1`)
- 상태: 승인 대기

## 배경 / 문제

1학기(2026-03-30 ~ 08-23)만 담고 있던 시트를 GY가 **2027-03-07까지 확장 완료**했다. 앱은 날짜 기반이라 주 블록이 늘어난 것 자체는 그냥 동작하지만, 세 가지가 남았다.

1. **학기 구분이 없다.** 2학기가 `1주`부터 다시 세는데 앱 제목은 `의학과 2학년 시간표 — 1주`로만 떠서, 3월 1학기 1주와 8월 2학기 1주가 화면상 똑같다.
2. **진입점이 하나뿐이다.** 상단 `⚙` 버튼이 개인 하이라이트 전용이라, 다른 기능(공지·가이드)을 붙일 자리가 없다.
3. **업데이트를 알릴 방법이 없다.** 앱·위젯을 고쳐도 친구들은 모른다. 카톡으로 매번 알리는 것도 한계.

## 비목표 (YAGNI)

## 설계 결정 (확정)

### A. 시트 (GY 작업)

주 블록 작성은 **완료**(49블록, 2027-03-07까지). 잔여는 **`공지` 탭 생성 1건**이며, `시간표` 탭 **오른쪽**에 만든다. `tools/make-notice-tab.gs`를 Apps Script에서 1회 실행하면 자동 생성된다.

> `공지` 탭이 첫 번째 시트가 되면 안 된다. `tools/extract.ps1`이 `xl/worksheets/sheet1.xml`을 하드코딩으로 읽어서, 순서가 바뀌면 30분마다 도는 스냅샷 Action이 엉뚱한 시트를 커밋한다. GAS 스크립트가 위치를 강제하므로 수동 생성만 피하면 된다.

파일명은 두 학기를 담게 되었으니 `v89_26시간표_GY`처럼 학기 표기를 빼는 것을 권한다(버전 배지에 그대로 노출됨). 필수 아님.

### B. 날짜 교정 안전장치 (축소판)

app.js `parseGrid()`와 위젯 `findWeekPicks()`는 둘 다 "i번째 블록의 월요일 = median(monday − 7i) + 7i"로 시트 날짜를 덮어쓴다. 연도 오타를 잡아주는 유용한 로직이지만, **주 블록을 하나 빠뜨리면 그 뒤 전부가 경고 없이 7일씩 밀린다.**

**조건 하나만 추가한다: 시트 날짜가 이미 월요일이면 덮어쓰지 않는다.**

```js
// app.js parseGrid()
const mondays = rawMon.map((m, i) => {
  const expect = baseMedian + 7 * i;
  if (m === null) return expect;
  if (m % 7 === MONDAY_MOD) return m;              // ← 추가 (MONDAY_MOD = 2)
  return Math.abs(m - expect) > 1 ? expect : m;
});
```

```js
// widget/timetable-widget.js findWeekPicks()
headers.forEach((h, i) => {
  const ex = base + 7 * i;
  if (h.monday % 7 !== 2 && Math.abs(h.monday - ex) > 1) h.monday = ex;   // ← 조건 앞부분 추가
});
```

- `serial % 7 === 2 ⟺ 월요일`은 실측으로 확인했다. 현재 정상 49개는 전부 통과, 과거 오타 2건(2025-06-15 · 2025-07-06)은 둘 다 일요일이라 여전히 교정 대상이다. 오탐 0.
- 현재 시트에서는 **한 번도 발동하지 않는다** — 49개가 전부 월요일이라 교정 분기에 진입조차 안 한다. 따라서 출력은 변경 전과 바이트 동일이어야 하고, 이를 검증 기준에 넣는다.
- 위젯은 라벨 표시를 안 바꾸기로 했지만 이 1줄은 넣는다. 같은 결함이 양쪽에 있다.

### C. 학기 · 제목

`index.html`의 고정 문구 `의학과 2학년 시간표 —`를 없애고 렌더 때 계산한다.

학기 판정의 정본은 `app.js` CONFIG의 표 하나:

```js
SEMESTERS: [
  { name: '26-1', start: '2026-03-30' },
  { name: '26-2', start: '2026-08-31' },
],
```

`semesterOf(monday)` = start가 monday 이하인 마지막 항목의 name, 없으면 `null`. 다음 학기엔 이 배열에 한 줄 추가하는 것이 전부다.

**표시 규칙** — 주차 라벨이 `N주` 꼴일 때만 학기명을 붙인다:

| 라벨 | 제목 |
|---|---|
| `20주` (2026-08-17) | `의학과 26-1 시간표: 20주` |
| `1주` (2026-08-31) | `의학과 26-2 시간표: 1주` |
| `방학` | `의학과 시간표: 방학` |
| `미정` | `의학과 시간표: 미정` |
| (빈칸 — 현재 0건) | `의학과 시간표` |
| 2주간 뷰 | 합친 라벨을 그대로 규칙에 태운다 — `1주–2주`는 `N주` 꼴이 아니므로 학기명을 붙이려면 **첫 주 라벨**로 판정한다. 첫 주가 `방학`이면(예: `방학–1주`) 학기명 없음 |
| 월간 뷰 | 그 달 1일 기준 — `의학과 26-1 시간표: 2026년 8월` |

방학 주를 학기에서 빼는 이유: 08-24 방학 주는 26-1로도 26-2로도 부를 수 없다. "라벨이 `N주`일 때만"이라는 규칙 하나로 경계 문제가 사라진다.

**라벨 폴백 제거**: `parseGrid()`는 A열이 비면 `(순번)주`를 지어낸다. GY가 `미정`을 채워 지금은 발동하지 않지만, B와 같은 부류(없는 값을 조용히 지어냄)라 함께 없애고 빈 문자열을 그대로 둔다. **없는 주차 번호를 지어내는 것보다 빈칸이 정직하다.** 현재 데이터에서 무영향임을 검증 기준에 넣는다.

앱 이름(`manifest.json`, `index.html`의 `<title>`, `apple-mobile-web-app-title`)은 `의학과 2학년 시간표` 그대로 둔다 — 학기와 무관한 이름이고, 바꾸면 이미 설치한 친구들의 홈화면 아이콘 이름이 흔들린다.

### D. 3줄 메뉴

`⚙` 버튼(`#btnHl`)을 **같은 자리에서** 3줄 아이콘(`#btnMenu`)으로 교체. 누르면 화면 아래에서 시트가 올라온다(기존 `.sheetpop` 스타일 재사용).

```
━━━━━━━━━━━━━━━━━━━━━━━
  🎨  개인 하이라이트 설정
  📢  공지사항                ●
  📖  설치 가이드 및 사용법
━━━━━━━━━━━━━━━━━━━━━━━
             닫기
```

- 안 읽은 공지가 있으면 **3줄 아이콘 자체에 빨간 점**이 붙는다. 메뉴를 열어야만 알 수 있으면 의미가 없다.
- 개인 하이라이트는 기존 `#hlpop`을 그대로 재사용하고 여는 경로만 바뀐다.
- 가이드는 같은 탭에서 `guide.html`로 이동. 그 페이지 최상단 "▶ 시간표 바로 열기" 버튼이 복귀 경로다.
- `guide.html`의 하이라이트 섹션에 `⚙`가 2곳(205행·207행) 박혀 있어 3줄 메뉴 문구로 고치고, 사용법 표에 메뉴 행을 추가한다.

### E. 공지사항

**데이터 출처**: 같은 스프레드시트의 `공지` 탭.

**형식** (1행 헤더, 2행부터 데이터, A열은 일반 텍스트 서식):

| A: 날짜 | B: 제목 | C: 내용 |
|---|---|---|
| `2026-08-12` | 2학기 시간표 반영 | 8/31부터 2학기 일정이 들어갔어요. |

**읽는 방법**: 시간표와 **분리된 별도의 작은 호출**을 쓴다.

```
GET /v4/spreadsheets/{ID}/values/공지!A2:C100?key={KEY}
```

`values.get`은 서식을 안 실어 응답이 ~2KB다. 시간표의 `includeGridData` 호출(라이브 12MB)과 완전히 독립이라 **공지가 실패해도 시간표가 멀쩡하고 그 반대도 마찬가지**다. `tools/extract.ps1`(스냅샷 추출기)도 건드릴 필요가 없다.

**호출 시점**: 앱 시작 시 1회 + 포그라운드 복귀 시(마지막 성공이 30분 넘었을 때만). 시간표의 5분 폴링에는 얹지 않는다.

**정렬**: 날짜 내림차순, 동률이면 시트 행 순서 유지(stable). 시트에서 어디에 추가하든 최신이 위로 온다. 날짜가 `YYYY-MM-DD` 문자열이라 사전순 비교 = 시간순 비교. 방어적으로 숫자(시리얼)로 오는 경우도 변환해 받는다.

**표시**: 최신 5개 펼침 + `이전 공지 N개 더 보기`. 각 항목은 날짜 · 제목 · 내용.

**상태 구분** — "판정 대상 아님"과 "판정 실패"를 절대 같은 분기로 흘리지 않는다:

| 상태 | 판정 | 화면 |
|---|---|---|
| 정상 | 200 + 행 있음 | 목록 |
| 빈 공지 | 200 + 행 0 | `아직 공지가 없어요` |
| 탭 없음 | 400 `Unable to parse range` | `아직 공지가 없어요` |
| 실패 | 그 외 오류·타임아웃·오프라인 | 캐시 있으면 목록 + `마지막 확인 8/11` · 없으면 `공지를 불러오지 못했어요` |

**캐시**: `localStorage.tt_notices = {at, items}`. 오프라인에서도 마지막 공지가 보인다.

**읽음 처리**: `localStorage.tt_notice_seen` = 마지막으로 본 공지의 날짜 문자열. 공지 패널을 열면 현재 목록의 최댓값으로 갱신.

**빨간 점 조건**: **알고 있는 목록**(라이브 성공 시 라이브, 아니면 캐시)의 최대 날짜 > `tt_notice_seen`. 아는 공지가 하나도 없으면 점을 띄우지 않는다 — 로드 실패를 "새 공지 있음"으로 둔갑시키지 않는다.

**작성 흐름**: 앱·위젯을 업데이트할 때마다 Claude가 한 줄짜리 항목 초안을 제시 → GY가 검수 → GY가 시트에 직접 입력. 시트는 이미 "링크 있는 사람 뷰어"로 공개돼 있어 **공지 탭에 쓰는 내용은 전부 공개**다. 이름·학번·연락처·개인 일정·내부 링크·시험 문제 관련 내용은 넣지 않는다.

## 검증 기준

**파서 · 학기**
- `state.weeks.length === 49`
- B 적용 전/후 `weeks.map(w => w.monday)` 배열이 **완전히 동일** (안전장치가 현재 데이터에서 무영향임을 증명)
- 라벨 폴백 제거 전/후 `weeks.map(w => w.label)` 배열이 **완전히 동일** (같은 이유)
- 제목 문자열 실측: 26-1 20주 / 방학 / 26-2 1주 / 미정 / 2주간 경계 / 월간 8월
- 공휴일 스캔이 실측 목록과 일치
- 375px에서 `document.body.scrollWidth <= innerWidth`

**공지**
- 정상 · 빈 탭 · 탭 없음 · 네트워크 실패 4가지 상태를 각각 확인
- 실패 시 빨간 점이 안 뜨는지
- 공지 호출을 강제 실패시켜도 시간표 렌더가 영향 없는지
- 읽음 처리 후 점이 사라지고, 새 항목 추가 시 다시 뜨는지

**위젯**
- 브라우저 모킹 하니스로 4개 크기 전부 (`errTexts` 비고 `set=true`)

**배포**
- push 전 `git pull --rebase origin main` (스냅샷 Action이 30분마다 커밋을 쌓는다)
- 유니크 쿼리(`?r=GUID`)로 반영 확인
